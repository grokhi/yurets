# Радио Юрец

Одна страница, один общий непрерывный эфир. **Единственный рабочий источник — Plex**.
Telegram и локальный источник сохранены в `src/streaming/sources/`; прежняя реализация
в `src/streaming/legacy_streamer.py`. Рабочее приложение их не импортирует и не запускает.
При недоступности Plex эфир сообщает об ошибке и повторяет подключение, без подмены источника.

## Локальный запуск

Нужны Python 3.12+, Poetry 2.2.1, FFmpeg с libmp3lame и системные часовые пояса.
Из корня репозитория:

```bash
poetry install
poetry run python -m src.geoip_update
cp .env.example .env  # только если .env ещё нет
# Заполните настройки Plex в .env, не коммитьте значения.
poetry run uvicorn src.main:application --host 127.0.0.1 --port 8000 --no-proxy-headers
```

Для разработки можно добавить `--reload`. Запускайте **один worker**: он ведёт общий
эфир и учёт активных подписчиков. SQLite хранится в `YURETS_DATA_DIR`; эта папка должна
быть постоянной и доступной для записи. `.env`, `.env.plex`, `data/` исключены из Git.
Настройки процесса имеют приоритет над файлами; `.env.plex` дополняет и переопределяет `.env`.

### Подключение Plex через браузер

Ссылка `app.plex.tv/desktop/...` — адрес веб-плеера, а не сервера музыки.
Можно не извлекать токен вручную:

```bash
poetry run python -m src.plex_link --server-id MACHINE_IDENTIFIER
```

Команда покажет официальную ссылку входа Plex. Откройте её в браузере, где выполнен вход,
и подтвердите доступ для **Радио Юрец**. Команда ждёт подтверждение, находит указанный сервер
и его музыкальную библиотеку, проверяет HTTPS-соединение и сохраняет `.env.plex` с правами
`0600`. Токен не выводится. Для нескольких музыкальных библиотек добавьте `--library-id ID`;
при неоднозначности команда выведет только названия и ID. Существующий файл не перезаписывается:
для нового подключения используйте `--output` и самостоятельно замените старую конфигурацию.
Если после подтверждения нужно разрешить домен сервера или выбрать библиотеку,
промежуточная авторизация хранится в `.env.plex.pending` с правами `0600` (исключён из Git).
Повтор команды продолжает подключение без нового входа; после успеха временный файл удаляется.

Для указанной в задаче ссылки machine identifier —
`d5891af14fca7c2135d962889ad817fcd48d3483`. Параметр `source=1` веб-приложения не используется
как доказательство ID музыкальной библиотеки: ID проверяется через API самого сервера.

Нужен сетевой доступ к `plex.tv`, `app.plex.tv` и HTTPS-адресу вашего Media Server
(часто отдельный хост `*.plex.direct`). В облаке разрешите именно найденный серверный домен.
Plex-авторизация в браузере не переносится автоматически в Python-процесс.

Альтернативно заполните:

- `YURETS_PLEX_URL`: адрес Media Server без пути и query, например `https://your-server.example:32400`;
- `YURETS_PLEX_TOKEN`: токен доступа к выбранному серверу;
- `YURETS_PLEX_LIBRARY_ID`: ID музыкального раздела;
- `YURETS_PLEX_SERVER_ID`: необязательная проверка идентификатора сервера.

Авторизация отправляется сервером в заголовке `X-Plex-Token`; браузер слушателя его не получает.
Редиректы Media Server не выполняются. TLS-проверка не отключается. HTTP поддерживается только
при явно заданном HTTP-адресе для доверенной локальной сети; browser-link выбирает HTTPS.

### Как устроен эфир

Plex API отдаёт каталог треков и ссылки на оригиналы. FFmpeg приводит каждый файл (включая
FLAC и M4A) к MP3 192 кбит/с, 44,1 кГц, stereo без заголовков между треками. Передача оригинала
в браузер не требуется. Следующий трек готовится заранее; локальный временный кэш ограничен
тремя треками и очищается при остановке. Первый запуск может занять время загрузки и конвертации.
Нужны место для оригинала одного трека и трёх MP3, CPU для FFmpeg. Максимум оригинала — 1 GiB
(`YURETS_PLEX_MAX_TRACK_BYTES`), таймаут конвертации — 5 минут. Многосоставные Plex Media
(несколько Part у одного трека) пока пропускаются.

## Плеер и интерфейс

Эфир запускается кнопкой Play стандартного аудиоплеера. До нажатия поток не загружается
(`preload="none"`). Пауза закрывает подключение; следующее нажатие Play возвращает
к текущему эфиру. Отдельной кнопки «Слушать» нет. Таблицы сохраняют строки целиком
и прокручиваются горизонтально на узком экране; доступна прокрутка с клавиатуры.

## Альбомы, расписание и очередь

`YURETS_TIMEZONE` задаёт день расписания. По умолчанию это `Asia/Tokyo`.
Автоматический режим каждый день детерминированно перемешивает альбомы библиотеки.
Внутри альбома соблюдается порядок **диск → номер трека**. Одинаковые названия разных
треков не считаются дублями. Если альбомов не хватает на сутки, список повторяется.
Альбом, начатый до полуночи, доигрывает целиком, затем начинается программа нового дня.

Ручной выбор: `YURETS_PLEX_ALBUM_IDS=["123","456"]` — ratingKey альбомов в желаемом порядке.
Изменения этого списка или часового пояса создают новую программу после перезапуска.
Если указанного альбома нет, это явная ошибка конфигурации, а не случайная замена.

Единый план хранится в SQLite. Эфир, очередь и расписание читают его, поэтому просмотр
очереди не меняет будущие треки. После перезапуска радио продолжает текущий по времени
трек, а не начинает день заново. Добавления в библиотеку попадают в следующий ещё
не сформированный дневной план. Удаление файла из Plex может временно сделать соответствующий
трек недоступным; сохранённый план не переписывается на ходу. Очередь — ближайшие пять
треков общего эфира; отдельного персонального плейлиста нет.

## Статистика

`/stats` и `/api/analytics` открыты всем без пароля. Публичны IP, страны,
история посещений и рейтинг слушателей.
`YURETS_ADMIN_PASSWORD` и `ADMIN_PASSWORD` больше не используются; старые значения
в окружении не мешают запуску. Токен Plex остаётся только на сервере.
Защищённые cookie уже включены по умолчанию (`YURETS_SECURE_COOKIES=true`).
Для публичного развёртывания используйте HTTPS. Для локальной разработки по обычному
HTTP при необходимости задайте `YURETS_SECURE_COOKIES=false`.

Хранятся посещения, время, IP, страна, user-agent, постоянный подписанный идентификатор
браузера и сеансы прослушивания. В интерфейсе есть периоды, страны, последние посещения,
дневные показатели и рейтинг по времени прослушивания. Это статистика браузеров,
не установление личности: очистка cookie создаёт нового слушателя.

Время поступает по продвижению аудиоплеера раз в 10 секунд, ограничивается серверным
временем и не удваивается при нескольких вкладках. Пауза, ожидание буфера и отсутствие
воспроизведения не считаются. Долгие разрывы heartbeat не заполняются автоматически;
при резком закрытии/фоновых ограничениях браузера возможен недоучёт последних секунд.
Счётчик не доказывает, что человек слышал звук, и не является защищённой от накрутки системой.
В выбранный период входят сеансы, начатые в этом периоде. Посещения по дням показаны в UTC.

Страна определяется локально по DB-IP Country Lite. Путь по умолчанию —
`geoip/dbip-country-lite.mmdb` относительно каталога приложения (в Docker —
`/app/geoip/dbip-country-lite.mmdb`). Задавать `YURETS_GEOIP_DATABASE` не нужно;
эта переменная остаётся переопределением для собственной Country MMDB.

База автоматически загружается с официального `download.db-ip.com` при сборке образа.
Для локальной установки или ежемесячного обновления выполните
`poetry run python -m src.geoip_update`, затем перезапустите приложение.
Загрузчик проверяет TLS, целостность gzip и формат MMDB перед заменой файла.
Если выпуск текущего месяца ещё не опубликован (404), проверяются два предыдущих.
При повреждении загрузки старая база сохраняется. Метаданные выпуска и SHA-256
записываются рядом в JSON. DB-IP Lite распространяется по CC BY 4.0:
[IP Geolocation by DB-IP](https://db-ip.com); атрибуция также показана в статистике.

Без установленной базы страна отображается как **«Не определена»**; для определения страны IP посетителей внешним геосервисам
не отправляются. За reverse proxy укажите только его сети в `YURETS_TRUSTED_PROXY_CIDRS`
и оставьте Uvicorn `--no-proxy-headers`, чтобы приложение само проверяло цепочку IP.

История очищается при запуске и раз в час, срок — `YURETS_ANALYTICS_RETENTION_DAYS` (90 дней).
Сохраняйте `radio.sqlite3` и `listener-cookie.key` вместе; ключ нужен для узнавания браузеров
после перезапуска. Для резервной копии работающей SQLite используйте SQLite backup API,
не копируйте только основной файл отдельно от WAL. Доступ к папке данных ограничьте владельцем.

## Docker

```bash
# Нужны заполненный .env и, при browser-link, .env.plex.
docker compose up --build
```

Образ ставит зависимости из lockfile, FFmpeg и DB-IP Country Lite. `./data` монтируется
в `/data`; встроенная база GeoIP находится отдельно, поэтому том её не перекрывает.
Для своей MMDB можно положить файл в `./data` и переопределить путь через
`YURETS_GEOIP_DATABASE=/data/имя-файла.mmdb`.
Compose с необязательным env-file требует версии 2.24+.

## Автодеплой на Timeweb

Workflow `.github/workflows/deploy.yml` запускается при push в `main`; повторный запуск
доступен в GitHub → Actions → Deploy to Timeweb → Run workflow. Одновременно выполняется
один деплой, уже начавшийся запуск не прерывается следующим push.

В GitHub → Settings → Secrets and variables → Actions нужен один repository secret:
`YURETS_SSH_PASSWORD` — SSH-пароль `root@147.45.100.176`. Пароль из окружения Codex
автоматически в GitHub не переносится. Для добавления секрета требуются отдельные права
GitHub; возможность push не означает наличие этих прав. Значение не хранится в репозитории
и передаётся SSH через переменную окружения, без аргументов командной строки.
Первое подключение запоминает SSH host key; следующие запуски используют `known_hosts`
из GitHub Actions cache и отклоняют изменившийся ключ. При удалении/вытеснении кеша это
снова первое подключение. Для перевыпуска ключа проверяйте сервер, а не отключайте проверку.

Скрипт `scripts/deploy-timeweb.sh` рассчитан на существующий сервер:

- проект `/root/yurets`, сервис `backend`, контейнер `yurets-backend-1`;
- Nginx обращается к `127.0.0.1:8000`; локальная правка Compose с этим bind сохраняется;
- `.env`, `.env.plex`, `./data` и настройки доверенного прокси остаются на сервере;
- перед обновлением создаётся приватная копия настроек, SQLite через backup API и cookie-ключа
  в `/root/.local/state/yurets-deploy/attempt.*`, а прежний образ получает тег
  `yurets-backend:previous-deploy`;
- допускается только fast-forward; посторонние изменения исходников и конфликты Compose
  останавливают деплой без перезаписи локальных файлов;
- сборка идёт при работающем старом контейнере; ошибка сборки не прерывает эфир;
- после переключения ожидается готовность Plex (до пяти минут), проверяются открытая
  статистика, очередь, расписание и декодирование MP3;
- если переключение или проверка не удались, запускается прежний образ с сохранённой
  конфигурацией. База автоматически не откатывается, чтобы не стирать новые посещения.

При откате исходники остаются на попытке обновления; работающий контейнер использует
предыдущий образ. Автоматические миграции, несовместимые со старой базой, требуют отдельного
плана обновления. Резервные копии не удаляются автоматически; следите за местом на VPS.
Логи деплоя доступны во вкладке Actions. GitHub показывает ошибку и при успешном откате,
чтобы не выдавать восстановление старой версии за успешное обновление.

## API и проверки

- `GET /health`: 200 при работающем эфире, 503 при отсутствии конфигурации/потока;
- `GET /stream`: общий MP3-поток; 503 до готовности, без локального/Telegram fallback;
- `GET /api/now-playing`: трек, исполнитель, альбом и позиция;
- `GET /api/queue?count=5`: фактические следующие элементы плана;
- `GET /api/schedule`: дневная программа альбомов с абсолютными временами;
- `GET /api/master`, `GET /api/stats`: диагностика эфира без данных посетителей;
- `POST /api/listening`: события плеера;
- `GET /api/analytics?days=30`: открытая статистика;
- `GET /stats`: открытая страница статистики.

```bash
poetry run python -m unittest discover -s tests -v
poetry run ruff check src tests
node --test tests/radio.test.cjs  # проверки логики браузерного плеера, Node 18+
```

Тесты не требуют настоящего Plex: проверяют API-контракт, пагинацию, авторизацию,
FFmpeg-конвертацию и декодирование, сохранение программы, порядок очереди, полночь/DST,
доступ к статистике, cookie и время прослушивания. Интеграцию с конкретной библиотекой
проверяйте отдельно после подключения: успешный `/health`, соответствие метаданных
и декодируемые байты `/stream` на переходе между треками.
